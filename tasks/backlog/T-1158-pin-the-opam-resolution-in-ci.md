## Goal

CI installs the same dependency versions on every run and on every compiler of the matrix, and a version bump is a reviewed change.

## Context

Review of PR #25 (T-0029): the CI job runs `opam install . --deps-only` against the live opam repository, so it resolved ppx_deriving 6.0.3 on OCaml 5.2 and 6.2.0 on OCaml 5.3, and the resolution changes whenever the repository does. The ppx_deriving generated code runs inside the compiler, so an unreviewed new version is a supply-chain surface (SECURITY.md). Options: a `egide.opam.locked` generated by `opam lock` and installed with `--locked` (one per compiler version, or a lock for the lowest and the highest), or `setup-ocaml` with `opam-repository-commit` pinned. Trade-off: a lock file drifts and needs a bump routine; a pinned repository commit is one line but moves all packages together.

## Acceptance criteria

- [ ] CI resolution is reproducible (same versions on two runs a week apart), by one of the options above, with the choice recorded in an ADR proposal or the task Log
- [ ] A documented routine to bump the pin
- [ ] `.github/` is a protected path: the change goes through the owner (AGENTS.md rule 6)

## Out of scope

Vendoring dependencies.
