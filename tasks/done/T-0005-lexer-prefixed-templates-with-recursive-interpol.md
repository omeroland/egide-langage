## Goal

`f"…{expr}…"` and other prefixes produce a TEMPLATE token holding literal parts and the token streams of interpolations, supporting nesting.

## Context

Spec rules: LEX-055. See docs/architecture.md and the role file `.claude/agents/syntax-engineer.md`.

## Acceptance criteria

- [x] `f"a{b}c"`, `sql"… {x} …"`, `f"{f"{x}"}"`, `{{`/`}}` escapes tested
- [x] Interpolation spans map to exact source positions
- [x] `r"…"` and `b"…"` are not templates

## Out of scope

Anything not listed in the acceptance criteria; create follow-up tasks.

## Log

2026-11-10 language-architect (owner-delegated, ADR-0017, security review resolution): LEX-055 end rule: `#` inside `{…}` is E0044; `\` consumes the next character first, then `{{`/`}}` collapse, lone `}` is E0044; char literals and nested strings tracked in interpolations; empty spec `{x:}` is a spec; literal parts delivered after brace collapse; template nesting limit 8 (E0044). E0601/E0602 live in the template/type phase, not in the lexer.

2026-11-10 language-architect (owner-delegated, ADR-0016): Q-0014 decided (LEX-055): literal parts are raw, `{{`/`}}` only lexer escapes, a backslash only protects the next character, interpolation `{expr[:spec]}` ends at the first `:` or `}` outside brackets (strings and templates tracked), spec raw without `{ } "` or line break, line break inside `{}` only in triple-quoted templates, keywords are never prefixes, triple-quoted templates dedented before splitting, E0044 for malformed interpolation. Sink prefixes rejecting `:spec` (E0601) belong to the template functions, not the lexer.

2026-11-11 syntax-engineer: `rb"x"` (LEX-053 vs LEX-055) is an extrapolation; raised as Q-0052 (tasks/blocked/Q-0052-rb-prefix-lex-053-vs-lex-055.md). The lexer implements option A until the language-architect decides.

## Outcome

Done (PR on branch `t-0005-lexer-templates`).

- `TEMPLATE` token (`Tokens.template`: prefix + parts; a part is raw literal text, braces collapsed, or an interpolation with its real token stream, exact positions, optional raw spec). Interpolations are read by the lexer itself (`token`), tracking brackets, strings, chars and nested templates; the expression ends at the first `:` or `}` at bracket depth 0.
- Diagnostics (all with fixed text, no source echoed): E0044 for a lone `}`, `#` inside `{}`, empty `{}`, `{ } "` in a spec, unterminated interpolation / line break in a single-line template, nesting deeper than 8 (reported once per outermost template, deeper templates are skipped as plain text, so the stack stays bounded); E0040 for an unterminated template literal.
- Triple-quoted templates: the margin (LEX-051) is computed on all lines including the lines of interpolations (their source text is cut from the input by character position), removed from literal text only; line breaks between two interpolations are kept.
- Tests: `compiler/test/syntax/test_lexer_templates.ml` (expect tests, typed position test, qcheck "template soup"), conformance `tests/conformance/lexical/template_*.egd` (14 files).

Design decisions (counter-hypotheses in the PR):
1. `tokens.ml` is now generated by `tools/gen/tokens.py` instead of `menhir --only-tokens`, because a token that contains tokens is a recursive type Menhir cannot write. The terminals stay declared for Menhir in `token_decls.mly` (was `tokens.mly`). Alternative rejected: storing interpolations as source ranges and re-lexing them on demand (no recursive type, but double lexing and a second place that must agree on positions).
2. (Open question Q-0052, tasks/blocked: A/B/C options, recommendation B; the lexer implements A until decided.) `rb"x"` is now a template (`rb` is a lower_snake non-keyword identifier other than `r` and `b`, LEX-055). Two T-0004 expectations that showed `IDENT STRING` were updated accordingly; LEX-053's "no `rb"..."`" is read as "no raw byte string".
3. T-0005's own `paths` were extended with `tools/gen/tokens.py`, `tools/check-generated.sh`, `CHANGELOG.md` for this task.

Review follow-ups (PR #28): B1 `triple_literals` was quadratic (20k lines, one interpolation per line, took 5 s); now a forward line cursor, 80k lines lex in 0.6 s, regression test `triple-quoted template with one interpolation per line is linear` (CPU bound 2 s). N2 fixed: a multi-line token (a `"""` string) inside the interpolation of a single-line template is E0044 at the opening brace. N3: the five ADR-0017 cases `tests/security/lexical/template_*` (backslash then doubled brace, comment marker, nesting depth 8/9/300) are skipped by the runner (phase 1 > phase 0); the reviewer ran them by hand: four E0044 at the declared positions, the depth-8 control passes. They were not run by this task.

Known limitations / follow-ups: see the PR (recovery after a malformed interpolation in a triple-quoted template can cascade; a nested multi-line string inside an interpolation is tokenised on the raw source lines, not dedented by the outer margin; E0601/E0602 and the AST shape (T-1041) are not part of this task).
